Algorithmic Trading Simulator

A full-stack paper-trading platform with a simulated stock exchange, real-time market data, and professional trading UI.

Go 1.26 TypeScript React 18 PostgreSQL 15 Redis 7 Docker

1. Overview

The Algorithmic Trading Simulator simulates an entire stock exchange in-memory using Go, providing a realistic paper-trading environment. It features a concurrent matching engine with Price-Time priority, synthetic market making, noise trader simulation, Geometric Brownian Motion price generation, and real-time WebSocket streaming — all wrapped in a professional React-based trading UI.

The system simulates 15 Indian stock market assets across 10 market cap segments (Large Cap, Mid Cap, Small Cap, Micro Cap/Penny, PSU, etc.) with realistic drift/volatility regime switching.

6. Matching Engine Design

The core matching engine is an in-memory, concurrent system built on Go channels:

  • Buffered Channels — orderStream (100k buffer) decouples REST handlers from the matching goroutine
  • Deterministic Execution — Single background goroutine processes orders sequentially, guaranteeing Price-Time priority without locks
  • Self-Trade Prevention (STP) — Blocks trades where both parties share the same UserID
  • Order Book Data Structures:
    • OrderSide — Price levels with BST-like sorted structure
    • OrderQueue — Doubly-linked list per price level (O(1) push/pop/remove)
    • OrderIndex — Map from order ID to node pointer (O(1) cancel)
  • LOBBuilder (Shadow Book) — Event-driven LOB maintained via MarketEvent stream; emits snapshots every 1s via Redis Pub/Sub
  • Supports Limit, Market, and Cancel order types

7. Simulation Layer

7.1 GBM Price Generator

Geometric Brownian Motion engine with ~100ms tick resolution. Each asset has independent drift/volatility parameters that transition through Markov states:

ParameterStatesTransition
DriftBear | Bull | Normal | FlatEvery 5–30 minutes
VolatilityPanic | Elevated | Normal | QuietEvery 5–30 minutes

7.2 Synthetic Market Maker

  • Places bid/ask ladders every ~100ms tick
  • Dynamic spread scaling based on volatility (0.3x to 3.0x)
  • Power-law notional scaling: baseConstant * price^scalingFactor
  • Volatility thinning — reduces quantity when volatility is high
  • Drift skewing — biases bid/ask quantities based on directional momentum
  • Operates under UserID 999999998

7.3 Noise Trader

  • Simulates retail order flow with realistic behavior
  • Pareto-distributed order sizes (alpha = 1.5 for heavy tails)
  • Momentum bias via exponential moving average of price
  • Contrarian behavior (15% chance to fade the trend)
  • U-shaped intraday volume (high at open/close, low at midday)
  • 70% market orders, 30% limit orders
  • Randomized UserIDs in range 900000000–909999999

11. Real-Time Data Pipeline

All real-time data flows through Redis Pub/Sub channels, making the system horizontally scalable:

ChannelContentThrottle
candles:{symbol}OHLCV candle updates (1s or 5s intervals)—
orderbook:{symbol}Order book snapshots1s
midprice:{symbol}Current mid-price updates—
prices:allAggregated price feed for all assets500ms
trades:{symbol}Recent trades (ring buffer, last 50)—

The WebSocket handler (ws.go) accepts topic-based subscriptions and streams from Redis to connected clients. Candle data is aggregated server-side and stored in TimescaleDB continuous aggregate views.
